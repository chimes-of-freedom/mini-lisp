# 词法分析实习报告

## 第一部分 语言形式化描述（正规文法）

### 语言简述
Mini Lisp 是 Lisp 语言的 Racket 方言的一个基础实现（子集）。
- 一个合法的 Mini Lisp 程序由一个或多个 S-表达式构成，S-表达式间使用 0 个或多个空白字符分隔。
- S-表达式分为组合式和特殊形式两种，二者形式一致，但语义有区别；每个 S-表达式的最外层是一对圆括号，中间是一个或多个参数，参数间用定界符分隔。
- 定界符包括左右圆括号、双引号和至少一个空白字符组成的符号串。
- 对于 S-表达式的每个参数，其可以为另一个 S-表达式、整型常量、浮点型常量、布尔型常量、字符串字面量、用户自定义标识符。对于第一个参数，还可以为特殊形式的标识符、算术运算符、逻辑运算符。
- 如果一个参数为字符串字面量，则需要用双引号包裹起来，且字符串内的双引号用 `\` 转义（转义符本身也作为字符串的一部分）；布尔型常量为 `#t` 或 `#f`。
- 字符串字面量参数和 S-表达式参数与其他参数使用 0 或多个空白字符分隔；其他类型的参数与其他非前述类型的参数使用至少 1 个空白字符分隔。
- 其他定义参见 Racket 方言。

### 文法定义
$$
G[S] = \{ V_N, V_T, P, S \}
$$

### 非终结符号集合
$$
V_N = \{ S, str\_next, dquote\_next, digits\_next, bool\_next, word, eq \}
$$

### 终结符号集合
$$
\begin{aligned}
V_T            &= id \cup const \cup special\_forms \cup aops \cup lops \cup delimiters, \\
\\
id             &= \text{G([a-zA-Z\_]\\w*)} - special\_forms,\\
\\
const          &= integer \cup float \cup bool, \\
integer        &= \text{G([\\+-]\\d+)}, \\
float          &= \text{G([\\+-]\\d+\\.\\d+)}, \\
bool           &= \{ \text{\#t}, \text{\#f} \}, \\
\\
special\_forms &= \{ \text{define}, \text{if}, \text{list}, \text{cons}, \text{lambda}, \text{display}, \text{quote}, \text{'} \}, \\
\\
aops           &= \{ \text{+}, \text{-}, \text{*}, \text{/} \}, \\
\\
lops           &= \{ \text{<}, \text{>}, \text{<=}, \text{>=}, \text{=} \}, \\
\\
delimiters     &= \{ \text{(}, \text{)} \}
\end{aligned}
$$

### 产生式
*简便起见，使用特定符号代表**一系列终结符或一个终结符号串**。定义如下：*
- $\text{<any\_except\_dande>}$：任一除双引号和转义符外的终结符
- $\text{<digit>}$：任一数位
- $\text{<define>}$：串 $\text{define}$
- $\text{<if>}$：串 $\text{if}$
- $\text{<list>}$：串 $\text{list}$
- $\text{<cons>}$：串 $\text{cons}$
- $\text{<lambda>}$：串 $\text{lambda}$
- $\text{<display>}$：串 $\text{display}$
- $\text{<quote>}$：串 $\text{quote}$
- $\text{<letter>}$：任一字母

$$
\begin{aligned}
\text{起始：} \\
S \to             &\text{(} \mid \text{)} \mid \verb+"+ str\_next \mid \\
                  &\text{+} digits\_next \mid \text{-} digits\_next \mid \text{<digit>} digits\_next \mid \text{<digit>} \mid \\
                  &\text{\#} bool\_next \mid \\
                  &\text{<define>} \mid \text{<if>} \mid \text{<list>} \mid \text{<cons>} \mid \\
                  &\text{<lambda>} \mid \text{<display>} \mid \text{<quote>} \mid \text{'} \mid \\
                  &\text{<letter>} word \mid \text{\_} word \mid \text{<letter>} \mid \text{\_} \mid \\
                  &\text{+} \mid \text{-} \mid \text{*} \mid \text{/} \mid \\
                  &\text{<}\ eq \mid \text{>}\ eq \mid \text{<} \mid \text{>} \mid \text{=} \mid \\
\\
\text{字符串字面量：} \\
str\_next \to     &\text{<any\_except\_dande>} str\_next \mid \text{\\}\ dquote\_next \mid \verb+"+ \\
dquote\_next \to  &\verb+"+ str\_next \\
\\
\text{整型、浮点型或布尔型常量：} \\
digits\_next \to  &\text{<digit>} digits\_next \mid \text{<digit>} \\
bool\_next \to    &\text{t} \mid \text{f} \\
\\
\text{用户自定义标识符：} \\
word \to          &\text{<letter>} word \mid \text{<digit>} word \mid \text{\_} word \mid \text{<letter>} \mid \text{<digit>} \mid \text{\_} \\
\\
\text{逻辑运算符：} \\

\end{aligned}
$$

## 第四部分 词法分析算法

### 项目结构
项目库 crate 模块结构如下：
```text
crate mini_lisp
└── mod scanner: pub
    ├── enum ScanError: pub     // 定义词法分析的两种错误：未定义符号和未定义 token
    ├── struct TableItem: pub   // 符号表条目结构，有成员 `index`（记录出现位置） 和 `value`（可为空）
    ├── enum TokenType: pub     // token 类型
    ├── struct TokenUnit: pub   // 词法单元
    ├── enum ValueType: pub     // `TableItem.value` 类型
    ├── fn scan: pub            // 词法分析功能入口，接受整个文本字符串，返回 token 序列和符号表
    ├── mod utils: pub(self)
    │   ├── fn chars2bytes: pub                 // 根据字符数计算字节数
    │   ├── fn detect_invalid_char: pub(self)   // 检测是否存在未定义符号
    │   ├── fn generate_valid_chars: pub(self)  // 生成合法符号列表
    │   ├── fn parse_const: pub(self)           // 解析数据型常量
    │   ├── fn recog_cmp: pub(self)             // 识别逻辑运算符 token
    │   ├── fn recog_const: pub(self)           // 识别常量 token
    │   ├── fn recog_id: pub(self)              // 识别用户自定义标识符 token
    │   ├── fn recog_mark: pub(self)            // 识别左右括号
    │   ├── fn recog_op: pub(self)              // 识别算术运算符
    │   ├── fn recog_reserved: pub(self)        // 识别特殊形式保留字
    │   └── fn tokenize: pub                    // 接受一行文本字符串，解析串的首个 token 并返回其 `TokenUnit` 和 `TableItem`
    └── fn whitespace_cnt: pub(self)            // 计算前导空白字符数
```

```text
crate scan_tokens
```

### 源代码分析
重点分析 `tokenize()` 及其调用的 token 解析函数（`recog` 系列函数）的逻辑。

#### `fn tokenize()`
`tokenize()` 接受 1 个字符串以及该串的首字符在原文的行列号，解析其首个 token 并返回一个元组，包含对应的 `TokenUnit` 和 `TableItem` 实例。调用者 `scan()` 保证传入的字符串不带换行符且没有前导空白字符。

`tokenize()` 按一定顺序调用每类 token 的解析函数，当某个函数解析出 1 个 token 时立即返回对应信息。若所有函数均无法解析出 token，则视情况返回相应的错误信息：
- 若将字符串按定界符分割，取首个子串，子串中含有未定义符号，则返回 `InvalidCharacter`；
- 否则，返回 `InvalidToken`。

按顺序，`tokenize()` 调用如下解析函数：

#### `recog_mark()`
`recog_mark()` 识别左/右圆括号。检测传入字符串首个字符，若为左/右圆括号则解析出对应 token，否则返回空值。

#### `recog_const()`
`recog_const()` 识别常量。通过首字符是否为双引号判断首 token 可能为字符串字面量还是数据型常量:
- 若为双引号，则按字符串字面量对应自动机的算法进行解析；
- 若为其他字符，则对字符串按定界符（空白字符、左/右圆括号、双引号）分割，取首个子串，调用 `parse_const()` 进行数据型常量的解析。

由于 `recog_const()` 先于其他不包含定界符的 token 的解析函数调用，并且后续解析函数都将字符串按定界符进行了分割，因此不会出现误将字符串字面量中出现的“token”误解析为 token 的情况，如 `"a+b"` 或 `"+"` 中的 `+` 不会被解析为加法过程的 token。

#### `recog_reserved()`
`recog_reserved()` 识别特殊形式关键字。先将字符串按定界符分割，取首个子串，然后进行匹配：若为特殊形式关键字，或长度大于 1 且首字符为 `'`，则解析出对应 token；否则返回空值。后者识别了“单引号+非定界符”的情况。

#### `recog_id()`
`recog_id()` 识别一般定义下的标识符。先将字符串按定界符分割，取首个子串，然后遍历每个字符：若满足开头字符为字母或下划线、后续字符为字母或数字或下划线，则解析出对应 token，否则返回空值。由于 `recog_id()` 后于 `recog_reserved()` 调用，因此其相当于实现了识别非保留字标识符的功能。

#### `recog_op()`
`recog_op()` 识别算术运算过程的标识符。先将字符串按定界符分割，取首个子串，然后进行匹配：若为 `+`、`-`、`*` 或 `/`，则解析出对应 token，否则返回空值。

#### `recog_cmp()`
`recog_cmp()` 识别逻辑运算过程的标识符。先将字符串按定界符分割，取首个子串，然后进行匹配：若为 `<=`、`>=`、`<`、`>` 或 `=`，则解析出对应 token，否则返回空值。`<=`、`>=` 先于 `<`、`>` 匹配。
